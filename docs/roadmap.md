## 下一步：匹配分校准（暂缓）

**问题**：现在的五个维度权重（项目对口 0.45 / 年限 0.25 / 方向 0.15 / 技能 0.10 / 语言 0.05）
是凭直觉定的，没有数据支撑。分数看起来合理，但没人验证过「70 分以上的岗位是不是真的更适合投」。

**为什么暂缓**：开源 + 本地运行意味着拿不到用户数据，只能靠自建基准集，需要人工标注。

### A1. 基准集（优先）

自己造一套评测集，随代码发布、进 CI：

- 10 份不同类型的简历（应届/社招/转行/CV/后端/测试…）
- 20 个真实 JD
- 人工标注每条「简历 × JD」的相关度：`适合 / 勉强 / 不适合`

用它算**分数与人工判断的相关性**（Spearman 秩相关）：

- 相关性 ≥ 0.6 → 权重可信
- 相关性 < 0.4 → 权重需要重调，或者维度设计有问题

好处：以后调权重、改维度，跑一遍就知道是变好还是变坏。

**工作量**：标注 200 条（约 2 小时），评测脚本半天。

### A2. 本地行为洞察（可独立做）

每个用户在自己机器上积累行为数据（不出本机）：

| 事件 | 记录时机 |
|---|---|
| 查看详情 | 点「详情」 |
| 定制简历 | 启动生成任务 |
| 投递 | 点「已投递」 |

积累 ≥ 20 条后，在 Agent 页显示一句个人洞察：

> 你投递的岗位平均分 72，只查看没投的平均 61 —— 对你来说 70 分以上值得认真看

**价值**：帮用户判断「该看多少分的岗位」，不依赖任何服务端数据。
**工作量**：埋点表 + 一个统计函数，半天。

### A3. 个人权重（长期，可选）

在岗位详情页加两个按钮：「这个不适合我」「这个很合适」。
攒够 20 个标签后，本地用逻辑回归微调那五个维度的权重——**每个用户的权重是他自己的**。

风险：样本太少时容易过拟合，需要「标签数不足就退回默认权重」的保护。

## 其他待办（来自技术评审）

| 优先级 | 事项 | 说明 |
|---|---|---|
| P1 | 多简历管理 | 现在同类型简历只存一份，覆盖式保存 |
| P1 | 平台搜索扩展 | 目前只有 51job；BOSS 直聘风控强 |
| P2 | 移动端适配 | 只考虑了桌面 |
| P2 | 技能加权 | 区分 JD 的「核心要求」和「优先项」，进一步压标题党岗位 |
| P3 | 投递跟进 | 投递后 N 天没回音提醒（**注：这是产品功能，不是 agent 能力，优先级低**） |

## 已否决

| 想法 | 否决原因 |
|---|---|
| 「让模型自评回答」 | 多一次调用、经常自说自话；改为确定性一致性校验（见 `app/agent/verify.py`） |
| 主动推送提醒 | 属于产品功能而非 agent 能力，用户明确不需要「agent 感」 |
